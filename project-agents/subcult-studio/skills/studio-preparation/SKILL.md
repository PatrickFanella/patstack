# Studio preparation

Identify the product, intended audience and output. Resolve the Studio owner from project/global context; on Kvant it is ~/Work/Subcult/subcult-studio. Read Studio's AGENTS.md and [source routing](references/source-routing.md). SUBCULT's vault owns planning and indexes; Studio owns content, brand masters and preparation automation; each product owns executable behavior and factual technical claims.

For visual work, read the selected product's actual guide, tokens and manifest before changing assets or UI. Preserve user-edited SVG masters, licenses and imported provenance; change generators and source masters together when required. A general SUBCULT mood does not override approved light palettes, product typography, accessibility or existing components. Do not regenerate unrelated brands.

For copy and drafts, use the Product Claims Register and the relevant editorial source. Apply unslop and concrete product value. Brand metaphors are optional when they fit the artifact; do not force lore into error messages or invent available features. Naming/worldbuilding is a requested identity task, not a default implementation step.

For supporter work, treat older fixed daily/weekly/monthly promises as historical plans. The October support redesign requests shared light rewards, private Discord access and occasional BTS/exclusive releases without a promised schedule. Read the reviewed source identified in source-routing before reusing tier copy; proposed copy does not prove live Patreon, site or Discord state. Preserve existing task IDs, recurrence, schedules and runner state. This instruction migration does not authorize offer activation or publication.

Verify the requested source/asset hashes, parsing and relevant rendering or project checks. Report source, draft, approval, scheduling, dispatch and delivery independently. A saved draft, schedule ID or local export does not prove publication. Continue existing approved preparation without repeated confirmation; sending or publishing requires actual task authority and provider readback.
