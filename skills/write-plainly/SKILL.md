# write-plainly

Apply once per session to every user-facing response and documentation edit. Preserve facts, uncertainty, citations, quotations, technical identifiers and the author's voice. Remove filler, vague praise and canned transitions. Use concrete words and read the result as its audience. Do not invent opinions or evidence.

When an explanation did not land, restore the task context and restate the result, reason and next action in plain language. Prose edits do not authorize code changes or publishing.
