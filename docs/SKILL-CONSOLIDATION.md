# Skill consolidation, November 9, 2026

The approved change reduces the selectable Subsets collection from 221 owners
to 104, and the everyday core from 42 to 37. Profiles select owners; owners
load only the requested procedure and its needed resources. The procedure
library remains available without exposing every workflow stage as another skill.

## Explicit decisions

- Keep `ui-craft`, `studio-brand-system`, `opentui-screens` and `tv-candle-charts`.
- Remove `ui-cliche-audit`, `wcag-a11y-audit`, `brutal-hud-kit` and
  `solidity-audit` from discovery, profiles, relationships and public exports.
  Recoverable originals are under `archive/removed-skills-2026-11-09/` and are
  excluded from the runtime bundle.
- Combine PostgreSQL inspection and schema migration in `postgres-workbench`.
- Combine Temporal design and Python testing in `temporal-workflows`.
- Keep `prose-unslop` separate and in core; plain restatement is a conditional
  procedure under that owner.

## Consolidation model

`catalog/consolidation-2026-11-09.json` records every combined owner, former
qualification record, resource hash, new procedure path and retained constraint.
`catalog/retired-names.json` records historical names without discovery aliases.
Current membership is generated in [the group reference](../profiles/CATALOG.md).

The combined owners cover requirements, implementation planning, issues,
architecture, repository research, reviews, verification, Git, work recaps,
browser adapters, operations, orchestration, skills, session context, research,
writing, marketing, media, fiction and learning. Language-specific, security,
forensic, authentication, privacy and payment-operation expertise stays distinct.

Platform and host runbooks load conditionally through `fleet-ops-router`.
PostgreSQL analysis does not authorize a migration; infrastructure artifacts do
not authorize application. Review modes remain read-only unless a separate task
authorizes changes. Strict and multi-model reviews retain explicit invocation
limits. Browser adapters follow the current client-native tools and do not take
over another session. Story coaching generates no fiction; requested co-writing
is a separate mode. Drafting marketing copy does not publish or send it.

Each mode retains its original client restrictions. A combined routing owner
may be visible in several clients while an individual mode is unavailable there.
File compatibility does not supply tools, authentication, stop hooks or runtime
features. Explicit-only procedures keep that restriction inside their mode;
ordinary modes remain available through the common owner.

## Verification and rollout

Validate entrypoints, links, catalogs and relationships; run the repository
suite and resource-preservation checks. Exercise a receipt-backed transition
from a previous selection to renamed owners and roll it back in an isolated
fixture. These checks establish structure and installer behavior, not successful
execution of every procedure in every model or client.

Commit the reviewed source, build an immutable Subsets bundle, preview on each
target, and use the guarded host deployer. Preserve each host's previous bundle,
receipts, unrelated owners and local changes. Verify the selected core and fresh
discovery separately. An unreachable host remains unverified until it returns.
