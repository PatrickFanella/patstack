# Task-set ownership conflicts on Soyuz and Sputnik

Blacktower is distributed by its application/package owner. Soyuz has a Copilot
view into the native Codex plugin cache; Sputnik has a native Blacktower copy
and application views. Personal task selection must not replace those with
patstack's reference copy. The local-owner and qualification catalogs now name
that owner, and `build-agent-tools` and `operate-homelab` no longer select it.
The 40-skill core is unchanged. The personal selectable library now has 219
owners; native Blacktower remains outside that count.

Sputnik's `split-test-planner`, `story-diagnosis` and `ebook-concept-miner`
were reviewed against both their recorded predecessors and the current source.
The only difference from the pinned predecessors is the absence of tracked
Finder `.DS_Store` metadata. The current story
procedure additionally has the reviewed companion routes. No authored local
procedure or executable difference was found.

The bounded host reconciliation archives the complete three old directories,
with their exact current bytes and modes, through the existing installer's
verified backups. It requires their current snapshots to match the reviewed
plan and their content without `.DS_Store` to match a pinned predecessor.
This is an explicit reviewed retirement, not an ignored drift check or a
replacement installation baseline. It refuses a changed authored file.
Normal Subsets activation can then install the selected reviewed sources at
absent paths. To restore the original copies, roll back later selection runs
first, then the separate reconciliation transaction.

Validation requires every task set to plan without collisions on both hosts,
real activation of the formerly blocked union, return to core, preservation
of Blacktower views, and fresh discovery at the expected selected sources.

The real combined-set exercise exposed Subsets' two-minute subprocess timeout:
it terminated the Python writer while its journal was progressing. Subsets
alpha.6 retains the read timeout and allows journaled write commands to finish
under their existing locks and drift checks. The partial host transaction was
resumed from its original journal; no baseline or progress entry was reset.
The deployment pin now requires alpha.6 for the repaired task-set rollout.
